Section 3 — Data model & UX changes

What changes under the hood and in navigation to support the library model

1. Workout file — two new fields

Each equestrian workout gets difficulty and description added. Everything else stays the same.

Before

export default {
  "name": "Foundation 1",
  "audiences": ["equestrian"],
  "phases": [ ... ]
};

After

export default {
  "name": "Foundation 1",
  "audiences": ["equestrian"],
  "difficulty": "easier",
  "description": "Full-body compound strength to build your base",
  "phases": [ ... ]
};

Difficulty values: easier moderate harder — you assign these to all 11 equestrian workouts.

3. localStorage — two coexisting keys

The old schedule key is untouched. The library adds a new weekly-count key.

// Existing — schedule slots (unchanged)
riderStrength.completed
→ { "w1-0": true, "w3-2": true }

// New — library weekly counts
equestrian.weeklyCount
→ {
  "2026-W24": 3,
  "2026-W25": 1
}

Week key = ISO week of the Monday that started it.
Resets automatically — old weeks just don't show in the UI.
